# Соглашения

- Node.js ESM и TypeScript Pi extensions.
- Маленькие этапы с отдельной проверкой.
- Доменная логика не зависит от консольного интерфейса и файловой системы.
- Для правил сначала пишется тест, который должен стать красным.
- После изменения production- или test-кода запускать соответствующие Node.js checks и tests.
- Не добавлять комментарии внутри методов без необходимости.
- Не делать push, PR или merge.
- Pi является владельцем файловой памяти; Jev не переписывает канонические документы молча.
- Jev управляет логическими фрагментами контекста через typed-операции; Pi применяет их.
- `ADD`, `UPDATE`, `REMOVE`, `RETAIN`, `ROUTE`, `CONFLICT` являются операциями контекста,
  а не прямыми командами записи файлов.
- Уже отправленный модели prompt не редактируется; после изменения собирается новый.
- `TRANSIENT` можно удалить, канонические фрагменты переводятся в `obsolete` с журналом.
- Полнота поиска контекста — ответственность Pi; Jev Router выбирает из переданных кандидатов.
- Router и Verifier Jev используют разные typed-контракты.
- `APPROVE` должен ссылаться на фактические evidence, а probability Jev не заменяет build/test/diff.
- Неподтверждённые выводы хранятся как `HYPOTHESIS`, а не как канонический факт.
- Чувствительные фрагменты не передаются внешней модели без явной policy.

Примечание: правила контекстного протокола уточняются после этапов Router/Verifier и
проверяются отдельными сценариями конфликтов, недостатка evidence и утечки контекста.
